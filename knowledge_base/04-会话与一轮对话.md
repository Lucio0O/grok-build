# 04 会话与一轮对话

「会话」和「一轮」是 Grok Build 最重要的两个时间单位。搞混它们，后面的压缩、回退、子代理、Goal 都会讲不清。

---

## 会话是什么

会话是**一次持续的工作关系**，不是屏幕上的一个聊天框。它包括：

- 用户说过的话和模型回过的话
- 每一次工具调用和结果
- 待办清单
- 规划稿（如果用过规划模式）
- 每个用户提示对应的文件快照（为了回退）
- 用量、轮次计数
- 它拉起的子代理（子代理自己也是会话，挂在父会话下面）

每个会话有一个 ID（通常是系统生成的 UUID；脚本也可以指定）。磁盘上按「工作目录 → 会话 ID」分开放，默认在 `~/.grok/sessions/`。换机器时只要把家目录策略想清楚：会话跟着 `GROK_HOME` 走，不跟着 git 仓库走。

### 会话目录里有什么（产品视角）

不必背文件名，知道职责即可：

| 内容 | 作用 |
|---|---|
| 摘要索引 | 标题、时间、模型、消息数、父会话（分叉用） |
| 权威更新流 | 恢复界面和协议回放的主日志 |
| 模型侧历史 | 真正送进模型的消息 |
| 待办 / 计划 | 任务列表与 `plan.md` |
| 回退点 | 每个用户提示处的文件快照 |
| 压缩检查点 | 手动或自动压缩留下的状态 |
| 信号与反馈 | 用量、计数、用户评分 |
| 子代理元数据 | 孩子在哪；孩子的完整会话仍在会话树里 |

**权威对话流**是那份更新日志。`/resume` 靠它把屏幕和状态重建出来。模型侧历史可以在压缩后变得更短——那正是压缩的意义。

---

## 一轮是什么

一轮从「一条提示被承认」开始，到「这一次模型循环结束、用量落账」为止。

一轮里模型可以：

1. 只说话，不调工具
2. 调一批工具，再根据结果继续说
3. 拉起子代理或后台命令，自己先结束，等通知再被唤醒（那是**下一轮**）

所以：用户按一次回车，通常是一轮；但一次「把登录重构做完」的任务，往往是很多轮。Goal 模式就是故意跨很多轮，并且每轮结束后都可能被宿主再叫醒。

### 提示从哪来

不是只有用户打字。

| 来源 | 何时出现 | 用户是否当作自己说的 |
|---|---|---|
| 用户 | 回车、无头 `-p`、ACP 送提示 | 是 |
| 后台任务完成 | 开发服务器起来了、测试跑完了 | 否（系统唤醒） |
| 子代理完成 | 孩子交卷 | 否 |
| 工作流完成 | 脚本编排结束 | 否 |
| 通知排空 | 监视器等积压通知需要模型看 | 否 |
| 定时器 | `/loop` 到点 | 否 |
| 规划恢复 | 规划批准后接着干 | 否 |
| Goal 摘要 / 分类轻推 | 目标模式要模型继续或补证据 | 否 |

这些合成来源保证：**Agent 可以在人去喝咖啡时继续往前走**，同时不把系统消息伪装成用户原话写进提示历史。

## 一轮内部怎么走

用产品语言把循环拆开。

### 1. 承认提示

- 当前空闲：马上开始
- 当前忙碌：进队列，或「立刻发送」取消旧轮
- 斜杠命令若由宿主消化（例如 `/theme`），可能根本不进模型

### 2. 开工前的装配

- 解析 `@` 附件、技能、特殊指令
- 通知各扩展「一轮开始了」（遥测、记忆、企业逻辑）
- 允许扩展往模型可见文本里塞一小段（例如相关记忆）
- 把用户消息追加到对话状态

### 3. 模型循环

宿主把当前对话发给模型。模型回流：

- 普通文字（回答）
- 思考块（可折叠，可在设置里关掉显示）
- 工具调用

每来一个工具调用，就走手脚层闸门（[07](07-权限安全与沙箱.md)）。工具结果写回对话，再问模型。如此直到模型不再调工具，或触达取消、轮次上限、致命错误。

无头模式可以设「最多转几圈」，防止 CI 里空转烧钱。

### 4. 收工

- 用量入账（若后台子代理还活着，有些账会标成未完）
- 判断要不要自动压缩
- 记忆是否该落盘
- 有没有排着的下一条提示
- 通知「一轮结束」

界面上，用户看到的是流式出现的块；产品上，块都是协议更新，同一份更新既画 TUI，也画 IDE，也写权威日志。

## 会话的一生

```text
创建  →  工作 / 空闲常驻  →  （可选）休眠
                ↓
            恢复 / 分叉
                ↓
            完成 或 失败
```

### 创建

TUI 每次启动默认新开会话。ACP 由客户端发「新建会话」并带上工作目录。无头一次 `-p` 也是一个会话，只是用完就走；加上 `-c` / `--resume` 则接到旧会话后面。

### 恢复

读权威日志，重建对话状态、工具和 MCP。沙箱档在恢复时**冻在启动那次的选择上**——不能靠换一条 `--sandbox` 偷偷换隔离级别。这是安全产品决策：历史会话带着当时的围栏。

### 分叉

`/fork` 复制对话，得到新的会话 ID。可选在新的 Git 工作树里干，以免和原会话抢同一份工作区。父会话指针写在摘要里，Dashboard 能看出家族关系。

### 回退

`/rewind` 不是「撤销最后一次模型口误」，而是：

1. 列出每个用户提示对应的回退点
2. 用户选一个点
3. **磁盘上的文件**回到那时
4. **对话历史**截断到那时

没有 git 的话，被回退掉的改动就没了。产品文案必须说清楚：回退改的是真文件。

### 压缩

`/compact` 或自动压缩会改「模型从此往后看见的历史」，不一定删权威日志。所以「界面上还能翻到很早以前」和「模型是否还记得很早以前」可以不是一回事。压缩模式见 [11](11-记忆压缩与上下文.md)。

### 休眠与崩溃

长期没人占用的会话可以从内存卸下，磁盘保留。TUI 崩溃会在 `active_sessions` 里留痕，下次启动可提示。干净退出会擦掉这笔痕迹。

## 多会话并行时的心智

Dashboard 只展示**顶层会话**。子代理是顶层会话内部的劳动力，不单独占一行（父行会显示「还在干活」）。

多个顶层会话可以：

- 盯同一个仓库（有写冲突风险，fork + worktree 就是为了减这个）
- 盯不同目录
- 被不同客户端附着（你在 Dashboard 里「打开 / 偷看 / 派活」）

派活（dispatch）**永远开新会话**，不会悄悄复用一行里那个旧 Agent。这是为了让「再派一个审查员」语义稳定。

## 和账号、模型的关系

会话记录当时用的模型和后端，但不等于账号本身。换模型是会话内操作（`/model`）；换账号是登录层操作。用量展示和账单入口会随「OAuth 还是 API Key」而变：前者偏向 grok.com 额度，后者偏向控制台。

## 设计时常见误区

1. **把「一条气泡」当成一轮。** 一轮里可以有很多工具块和一段思考。
2. **把「会话」当成「窗口」。** 窗口可以挂到已有会话上；关窗口不等于删会话。
3. **以为 `/new` 会销毁磁盘。** 它只是当前界面换新上下文。
4. **以为回退只改聊天记录。** 它改文件。
5. **以为压缩删掉了用户指南里说的权威日志。** 默认策略是换模型侧历史；日志仍可支撑恢复和某些压缩模式。

---

## 读完本章你应该能讲清

- 会话 = 持久工作关系 + 磁盘目录。
- 一轮 = 一次被承认的提示所驱动的模型循环。
- 系统可以自己开一轮，而且不应假装那是用户原话。
- 恢复、分叉、回退、压缩作用在不同的「真相」上。
