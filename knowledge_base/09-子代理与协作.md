# 09 子代理与协作

主代理不必事事亲力亲为。它可以请「孩子」去做调查、规划或专项实现。孩子是**独立会话**：自己的上下文窗口、自己的工具集、干完把摘要交回父母。这一章讲为什么要这样、怎么委派、风险在哪。

---

## 为什么要有子代理

主会话的窗口是稀缺资源。若主代理自己把整个仓库读一遍再改，早期读到的内容会把窗口撑满，后面真正的实现反而被挤掉。

子代理把「读和想」花在自己的窗口里，只把**结论**带回主窗口。同时，多个孩子可以并行：一个探认证、一个探计费、一个跑测试。

默认开启。可用配置或环境变量整段关掉——关掉后主代理只能自己干。

---

## 智能体档 vs 人格

这两个词在界面上挨着（`/config-agents` 两个页签），含义不同。

| | 智能体档（Agent） | 人格（Persona） |
|---|---|---|
| 配什么 | 整个会话：模型、工具、提示、技能 | 叠在子代理提示上的行为层 |
| 用在哪 | 主会话或子代理 | 只用于子代理 |
| 控制什么 | 会什么、用什么模型 | 语气、产出格式、输入输出契约 |
| 例子 | `grok-build`、`explore`、`plan` | `researcher`、`concise` |

孩子**永远先是某种档**（例如 `explore`），再**可以**叠人格。主代理拉起孩子时，并不传人格名字；人格通过解析规则和角色落到孩子头上。用户在人格页签里编辑的是「这类孩子应该像谁」，不是「这一次点名请谁」。

---

## 内置三类孩子

| 类型 | 定位 | 会不会改文件 |
|---|---|---|
| 通用 | 什么都能做的默认劳动力 | 会（除非再加能力限制） |
| 探索 | 搜、读、列、必要时跑只读命令 | 不会 |
| 规划 | 摸清现状，写出可执行方案 | 不会 |

项目或用户可以用同名定义盖住内置，也可以加新类型。菜单和可调用集合保持一致：关了的类型，模型也叫不着。

深度默认限制为**一层**：孩子不能再开孙子。这是在控费用和复杂度。产品上不要画「无限代理树」的饼。

---

## 一次委派怎么发生

```text
主代理判断「这块适合交给探索员」
  → 调用拉起子代理
      任务说明、短标签、类型、是否后台、
      能力模式、是否隔离工作树、工作目录……
  → 解析层算出孩子的最终模型、提示、工具、隔离
  → 孩子作为独立会话开跑
  → 前台：主代理等孩子交卷
    后台：立刻拿到孩子 ID，稍后取输出
  → 孩子结束 → 父母被合成轮叫醒，读摘要继续
```

解析时的覆盖顺序（高到低）大体是：这一次显式指定 → 角色默认 → 人格默认 → 父母。隔离比较特殊：前三步一样，缺省往往是「不隔离」，而不是继承父母是否用了工作树。

若指定的人格找不到或说明书读失败，拉起失败，而不是默默用一个空人格——避免「看起来请了审查员、其实没带审查标准」。

恢复一个已结束的孩子（接着聊）会校验类型/人格是否还对得上；模型差异可以软忽略。这是为了「续上同一个人」，而不是「拿着旧 ID 换一套灵魂」。

## 能力模式

委派时可以再裁一套工具：

| 模式 | 大致允许 |
|---|---|
| 只读 | 读和搜 |
| 读写 | 读和改 |
| 执行 | 读和命令/任务控制 |
| 全部 | 不裁 |

探索/规划档本身已偏只读；再叠「只读」是双保险。通用档 + 全部 + 共享工地，等于再请了一个和父母同样能写的同事，适合明确的实现分工，不适合「随便去看看」。

---

## 隔离：共享工地还是新工作树

- **不隔离（默认）**：孩子和父母看同一份文件。探索类最合适。两个会写的 Agent 同时改，可能互相覆盖。
- **工作树**：给孩子一份 Git 工作树，改动先留在自己那边。适合真正并行的实现，或 `/fork` 出的顶层同伴。

工作目录和「工作树隔离」互斥：要么你指定去哪个已有目录，要么系统分一棵新树。续跑旧孩子时沿用它原来的目录。

---

## 人格上的输入输出契约

人格可以声明「我需要哪些输入文件、会产出哪些产出文件」。父母据此知道该塞什么路径、去哪取结果。这样可以把人格串起来：审查员的笔记成为下一人格的输入。

契约是约定，不是内核强制的文件系统事务。产品上它降低「孩子交卷了但文件在哪」的沟通成本，不能替代检查点。

---

## 和 Dashboard、任务面板的关系

- Dashboard 只列**顶层**会话。孩子不占一行；父母行会显示「还在干活」。
- 任务面板同时看：孩子、后台命令、监视器、定时循环。
- Leader 重启后会尝试把孤儿孩子的状态对齐，避免界面上挂着幽灵任务。

用户问「我怎么同时看三个审查员」时：如果他们是子代理，去任务面板；如果他们是 `/fork` 或 Dashboard 派出来的顶层会话，去 Dashboard。

---

## 费用、窗口、治理

子代理各自消耗窗口和额度。并行能省墙钟时间，但通常更费。无头里可以用「禁止所有 Agent」或「禁止某一类」把委派关掉，适合预算敏感的 CI。

权限和沙箱：孩子默认走自己的会话策略。父母处于规划模式**不会自动**让孩子也只能写 `plan.md`。安全方案若要求「规划期间整个家族只读」，必须在委派时选探索/规划档或只读能力，而不能只开父母的规划开关。

---

## 产品叙事建议

对外讲子代理，用「请同事」而不是「多智能体平台」：

- 探索员：去把地图画回来
- 规划员：去把施工图画回来
- 通用同事：按你的说明把一块活干完
- 人格：同事的风格和交付格式
- 工作树：要不要给同事单独一张桌子

主代理仍对用户负责：孩子的摘要进主对话，用户主要和父母说话。

---

## 读完本章你应该能讲清

- 子代理 = 独立窗口的孩子会话，用来省主窗口、换并行。
- 档决定会什么，人格决定像谁。
- 默认同工地、一层深度、三类内置。
- 规划门闩和写文件能力不会自动传给孩子。
