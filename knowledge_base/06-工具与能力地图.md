# 06 工具与能力地图

模型不会「直接改你的硬盘」。它只能点名调用工具；宿主决定答不答应、怎么执行、结果怎么回去。本章按**用户能感知的能力**分组，并说明内置工具和外部 MCP 的差别。

---

## 总原则

1. **模型点菜，宿主做菜。** 界面上看到的「正在读文件 / 正在跑测试」是工具执行，不是模型幻想。
2. **工具有种类。** 读、改、执行、上网、任务控制……种类影响默认批不批准、子代理能不能用。
3. **同一件物理事可以有多套名字。** 默认是 Grok Build 自己的名字；还有精简描述版、按行哈希编辑版、以及兼容其他助手的工具面。对用户讲默认名即可。
4. **外部工具走另一扇门，但最终仍是「一次调用」。** MCP 用来接公司内部系统和 SaaS，不把它们编进 grok 二进制。

## 能力地图

### 读懂仓库

| 能力 | 典型工具 | 用户能指望它做什么 |
|---|---|---|
| 读文件 | 读文件 | 看源码、配置，也能处理部分 PDF/图片等 |
| 列目录 | 列目录 | 浏览结构 |
| 内容搜索 | 搜索 | 按正则在仓库里找（底层是高性能搜索） |
| 代码导航 | 工作区索引 | 跳转到定义/引用一类的结构化查询（可关） |
| 语言服务 | LSP 工具 | 诊断、格式化等，默认不一定露出 |

这些默认**不问人**。团队若把某路径视为机密，应下发 deny 规则或沙箱 deny，而不是指望模型自觉。

### 改代码

| 能力 | 思路 |
|---|---|
| 精确替换 | 给出旧字符串和新字符串，按匹配改。可全替换。空旧串表示新建文件 |
| 补丁应用 | 一整块补丁，带模糊匹配，适合多处一起改 |
| 行哈希编辑 | 不靠容易过期的行号，而靠行内容的锚点，降低「文件已被人改过」时改错行的概率 |

改完后：

- 界面出现差异
- 变更被记到「谁改的」（Agent 还是外部编辑器）
- 当前用户提示的检查点会收进这些改动，供回退

规划模式下，除 `plan.md` 外的编辑会直接失败。这是工具层硬拒，不是礼貌劝阻。

### 跑命令

终端工具可以前台跑、也可以后台跑。前台会占着这一轮等到结束（或用户 `Ctrl+B` 把它降到后台）。后台立刻返回任务号，模型稍后去取输出，或等「做完了」的通知再被唤醒。

配套能力：

- 取输出 / 等待多个任务 / 杀掉任务
- 按行监视日志（适合「测试一失败就叫醒我」）
- 定时调度（`/loop` 是给用户的包装）

命令是权限和沙箱最敏感的面。链式命令按段检查：前面是 `ls` 不代表后面的删除也被自动放行。详见 [07](07-权限安全与沙箱.md)。

### 上网

- **搜索**：问公开网上的资料
- **抓取**：把某个 URL 变成可读文本

进程内的联网（模型 API、搜索、抓取、部分 MCP）和「子进程能不能上网」是两件事。Linux 沙箱可以挡住子进程网络，但不自动切断 Grok 自己去搜网页。讲安全方案时必须拆开。

抓取有基础的来源限制，权限规则也可以按域名写。

### 协作与节奏

| 能力 | 作用 |
|---|---|
| 待办 | 把大任务拆成可勾选步骤，界面有任务条 |
| 问用户 | 结构化选择题，避免模型在关键分岔上瞎猜 |
| 拉起子代理 | 并行专项劳动，见 [09](09-子代理与协作.md) |
| 进出规划 | 见 [10](10-计划目标与工作流.md) |
| 更新目标 | 目标模式下的进度与「我声称做完了」 |
| 工作流信号 | 脚本编排与宿主之间的握手 |
| 技能 | 打开某份作业指导书 |

### 记忆

开启跨会话记忆后，模型可以搜索和读取记忆库。用户也可以说「记住……」写进 Markdown 记忆文件。默认关闭。见 [11](11-记忆压缩与上下文.md)。

### 媒体与发布（可选）

注册表里还有图像/视频生成与编辑、应用发布一类工具。它们是否出现取决于产品开关、账号档位和当前工具集，不能当成每个用户默认都会的能力。对外承诺前先对应当前发布说明。

## 模型怎么「看到」工具

会话开工时，宿主根据智能体档、能力模式、命令行白名单/黑名单、子代理策略，算出**这一次**露出哪些工具。每条工具带一份给模型看的说明书（名字、参数、何时用）。

精简工具集用更短的说明书，省窗口。子代理的「只读 / 读写 / 可执行 / 全部」从种类上裁剪，而不是偷偷留一个同名工具再在执行时拒绝——那样模型会反复撞墙。

工具还可以在结果之外附带**系统提醒**（例如「你有未完成的子代理」「发现了新技能」）。提醒是给模型的旁白，不一定原样印成用户气泡。

## 内置工具 vs MCP

| | 内置 | MCP |
|---|---|---|
| 谁实现 | Grok 二进制里 | 外部进程或 HTTP 服务 |
| 典型例子 | 读文件、改文件、跑命令 | 公司工单、内部 RPC、浏览器自动化 |
| 模型怎么发现 | 开工就在清单里（未被裁掉的话） | 数量可能很多，先搜索再调用，或使用 `服务器__工具` 这种限定名 |
| 治理 | 读/改/命令等规则类 | `MCPTool(...)` 规则；项目级要文件夹信任 |
| 输出过大 | 各工具自己的截断 | 有总上限，多的落到会话目录里，避免撑爆窗口 |

「接 GitHub / Jira / 内部知识库」应走 MCP 或插件自带的 MCP，而不是提需求「请写进 grok 内核」。内核保持通用手脚，生态保持可替换。

## 计算机中枢（只需一个比喻）

可以把工作区想成「本机工具服务器」，把 MCP 想成「外援工具服务器」。中间有一个中枢：

- 统一注册、搜索、调用、取消
- 本地实现可以盖住远程同名能力（影子），避免又走一遍网络
- 会话绑定后，工具看到的是这份工作区，而不是别人的目录

对用户，中枢不可见。对架构，它解释了「为什么 IDE 和终端能调同一套文件/Git 能力」。

## 后台与长任务在工具层的位置

用户以为的「它在边聊边编译」，拆开是：

1. 终端工具带「后台」参数，或用户把前台任务降级
2. 任务号进入任务面板（`Ctrl+G` 一类入口）
3. 任务结束 → 合成一轮，模型被叫醒看结果
4. 监视器按行推送；定时器按间隔推送

所以「挂着的工作」会让 Dashboard 上这一行继续显示正在工作，即使当前没有模型在说话。产品文案不要把「空闲」定义成「模型没在吐字」。

---

## 能力被裁掉时的表现

无头 `--tools` / `--disallowed-tools`、子代理能力模式、智能体白名单，都会让某些工具从模型眼前消失。消失后模型不应再叫到它们；如果提示词里还写着旧名字，就会出现「它一直想用某个已禁用能力」。自定义全量提示时，要用模板变量引用工具名，并在工具不存在时整段省略。

禁止子代理用特殊写法（例如「禁止 Agent」或「禁止 Agent(explore)」），这是无头自动化的常见需求：只许主代理自己看代码，不许再开孩子烧钱。

## 产品经理怎么用这张地图做范围管理

- **默认承诺**：读、搜、改、命令、网页、待办、子代理、规划。
- **需开关再承诺**：记忆、LSP、代码索引、语音、媒体生成、外部 OTEL。
- **需集成再承诺**：任何一家 SaaS 的「官方按钮」——那是 MCP/插件，不是内核功能。
- **需安全评审再放开**：一律放行、自定义沙箱、项目 Hooks、远程 MCP。

---

## 读完本章你应该能讲清

- Agent 的能力 = 工具清单 × 权限 × 沙箱 × 当前档位。
- 读和改、前台和后台、内置和 MCP，是三组独立区分。
- 长任务靠任务号和合成轮，不靠模型一直占着聊天。
