# 11 记忆、压缩与上下文

模型能一次看的内容有限。Grok Build 用三套机制对付这个限制：**本会话压缩**、**跨会话记忆**、**窗口用量估计**。它们解决的问题不同，不要卖成一个功能。

---

## 窗口是什么

每一轮送给模型的，是系统提示 + 对话（含工具结果）+ 本轮注入。这堆东西按「大约多少 token」来计量。界面 `/context`、`/session-info`、自动压缩门槛，用的是同一套粗估（例如按字节粗算，图片另有约数）。它不是账单上的精确 token，而是**大家用来说话的同一把尺**。

配置里可以设「窗口用到百分之多少就自动压缩」，默认大约在八成以上。模型自己的窗口大小来自模型配置。

工具结果过长会被裁剪；MCP 过大输出会溢到会话目录。这些是「先别让单次结果撑死窗口」，和压缩「把旧对话收起来」是两层。

---

## 压缩：给本会话腾地方

长会话里，早期试错对后面往往只剩「当时决定了用方案 B」。压缩把早期轮次收成模型还能用的形态，腾出后面的位置。

### 谁触发

- 用户 `/compact`，还可以加一句「请保留鉴权实现细节」
- 窗口接近上限时自动压缩，界面会提示
- 真的溢出了，走恢复路径再压一次
- 可选两遍压缩：先在后台预做第一遍，减少突然卡一下的感觉

压缩时，记忆落盘会和压缩互斥一会儿，避免一边摘要一边改记忆索引。压完可以再检索记忆，把相关块重新注入——旧对话没了，长期事实还在。

### 压完模型还能看见多细

有几种模式（会话或环境可配）：

| 模式 | 模型侧看到什么 | 适合 |
|---|---|---|
| 摘要（默认） | 旧历史被整段换成摘要 | 大多数编码任务 |
| 全文指针 | 知道完整日志还在、如何指向它 | 要回溯原话 |
| 分段 | 旧内容在分段文件里，带索引 | 只要某几段细节 |

Grok Build 的主策略是**整段替换**：这是编码助手的选择——后面的实现不需要早期试错全文。Grok Chat 类产品会用另一套「留尾巴、分块」策略；同一套压缩引擎，宿主不同。

权威界面日志通常还在，所以用户仍可能翻到旧气泡，而模型已经看不见原文。客服话术应区分「你还能翻到」和「它还记得」。

压缩检查点写在会话目录，必要时可回到压缩前的模型历史。

---

## 记忆：跨会话的长期便笺

默认**关**。开了之后，新会话可以想起旧会话里保存过的约定、排障步骤、架构决定。

### 怎么开

优先级从高到低：命令行强制关 → 命令行实验开 → 环境变量 → 配置文件 → 默认关。会话中途 `/memory on|off` 只影响本会话，关了不再暴露记忆工具，磁盘上的文件保留。

### 存哪儿

Markdown 文件，外加搜索索引：

- 全局一份：跨项目的个人习惯
- 每个工作区一份：这个仓库的约定（用仓库身份区分，同一远程的多个克隆/工作树共享）
- 各会话的日志：某天某次聊了什么主题

搜索是「关键词 + 可选的语义向量」混合，并做去冗余，避免把十段几乎相同的话都塞回去。文件变更会触发重新索引。

自动保存发生在会话结束：用元数据写一份短摘要（几条主题、条数、时间），**不调用模型**，也**不记录命令和路径**。太短的闲聊跳过。更像样的「把今天的决定写下来」用 `/flush`：这时才请模型总结，再入库。

用户也可以说「记住……」或 `/remember`，直接追加到全局或工作区便笺。`/remember` 在记忆总开关关掉时往往仍可用——它更像「写进便笺的快捷方式」。

### 做梦（合并整理）

`/dream` 一类流程会把分散的记忆合并去重。像人睡觉时整理笔记，所以叫这个名字。整理时会加锁，避免两个会话同时合并。

压缩之后，宿主会按当前任务再搜一遍记忆，把丢掉的长期事实补回来。这是压缩和记忆唯一必须一起讲的接头。

## 和项目规则、技能的差别

| 机制 | 时间范围 | 谁写入 | 每次是否在场 |
|---|---|---|---|
| 项目规则 | 和仓库同寿 | 人（进 git） | 是 |
| 技能 | 和工序同寿 | 人（进 git 或插件） | 相关才在 |
| 记忆 | 跨会话、可过期可合并 | Agent 或人 | 检索命中才在 |
| 压缩摘要 | 本会话后半段 | 系统 | 压完之后一直在（以摘要形式） |

「我们组永远用 pnpm」应写进 AGENTS.md，不应指望记忆。记忆适合「上周我们决定计费用方案 B，还没写进文档」。

---

## 隐私

记忆文件在用户磁盘上，可能含项目事实。自动结束摘要故意不写命令和路径。`/flush` 会更富，也就更敏感。企业若不准落这类文件，应保持默认关闭，并在硬性配置里锁死。

压缩摘要会进入模型侧历史，也就可能进入后续请求。不要假设「压完就从所有日志消失」。

---

## 产品怎么讲「它忘了」

用户说「它怎么忘了早上说的」，按这个清单查：

1. 是否已经自动压缩？看通知和 `/context`
2. 压缩模式是不是只留摘要？
3. 记忆开了吗？开了有没有 `/flush` 过？
4. 是不是新会话，而约定只存在旧会话、又没写进规则？
5. 子代理有自己的窗口，父母只拿到摘要——细节本来就不在父母脑子里

多数「遗忘」是窗口机制，不是模型突然变笨。产品应提供可见的窗口占用和压缩提示，而不是让用户猜。

---

## 读完本章你应该能讲清

- 窗口用同一把粗尺来显示和触发压缩。
- 压缩改本会话模型历史；记忆跨会话；规则进 git。
- 默认记忆关闭；自动结束摘要很克制；真正沉淀用 flush。
- 「我还能翻到」≠「模型还记得」。
