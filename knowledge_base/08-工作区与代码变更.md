# 08 工作区与代码变更

工作区是 Agent 的「工地」：当前目录、文件、Git、差异归因、回退点、可选的隔离工作树。没有工作区，工具只是一堆动词；有了工作区，这些动词才知道对象是谁。

---

## 工作区管什么

用一句话： **会话绑定到一个目录后，所有读改搜、Git、检查点、文件监听，都以这份目录为真相。**

它负责的产品能力：

- 当前工作目录和其中的文件视图
- Git（以及兼容的其它 VCS）状态、差异、提交相关操作
- 「这次 Agent 改了哪些行」和「用户在编辑器里改了哪些行」
- 每个用户提示处的回退包
- 是否用隔离 Git 工作树给分叉或子代理
- 把文件系统事件变成「工作区里发生了什么」
- 作为工具服务器，把同一套能力暴露给 IDE 协议

配置、账号、模型不在工作区里。那些是家目录和云端的事。

---

## 一次编辑的完整故事

以「把函数改名」为例：

```text
模型申请精确替换
  → 权限和沙箱放行
  → 在工作区文件系统上改字节
  → 发出「文件已写」通知
  → 差异追踪器把这次写入记成 Agent 行为
  → 本轮或本条用户提示结束时，打一个回退包
       （文件快照 + 这段差异 + 可选 Git 域信息）
  → 界面显示差异；用户可以接受/拒绝某些块（若界面提供）
  → 用户若 /rewind 到更早的提示，这些文件回到那时
```

三份「历史」不要混：

| 历史 | 回答的问题 |
|---|---|
| Git 提交 | 团队共享的、有意保存的版本 |
| 回退点 | 「刚才那句提示造成的工地状态」，不一定提交过 |
| 对话日志 | 当时说了什么、调用了什么 |

`/rewind` 走回退点，不自动 `git revert`。没有提交时，回退就是唯一后悔药，而且是破坏性的。

---

## 差异怎么归因

工地上同时可能有：

- Agent 写入
- 用户在 IDE 里保存
- 格式化工具改了一大片

追踪器把变更按块分开，并尽量标成「Agent」或「外部」。产品价值：

- 回顾「它到底动了哪些地方」
- 接受/拒绝可以按块，而不是整文件
- 回退包知道该还原哪一段
- 可选地把规模记入用量/分析（仍受隐私开关约束）

文件监听提供「磁盘变了」的信号，再丰富成工作区事件。Agent 自己的写入和外部写入走不同入口，避免把自己的写再当成外部噪音。

---

## Git 在产品里的角色

Agent 可以用命令行跑 git，也可以走结构化接口（状态、差异等）。产品没有强迫「每次改动都自动提交」——默认是工作区脏着，由用户或技能（例如 commit 技能）决定何时落库。

状态扫描会限制并行度，以免在进程数受限的环境里把自己打崩。这是稳定性，不是功能。

`/fork --worktree` 和子代理的「隔离 = 工作树」走快速工作树能力：尽量用拷贝加速的方式分出一份目录，让两个 Agent 不抢同一组未提交改动。隔离默认常常是「不隔离、共享工地」，因为大多数委派是只读探索。**会写文件的孩子 + 共享工地 = 互相覆盖**，要在说明里写明。

---

## 检查点与提示边界

每条用户提示是一条自然边界：

- 开始提示：记下「动手前」
- 结束提示：收进这一段的文件和差异

因此回退列表按「你说的那几句话」排列，而不是按每一次工具调用排列。产品选择是：用户记得自己说过什么，不记得中间十五次替换。

IDE 里的「按提示撤销」和终端 `/rewind` 是同一思想的两个皮肤。

---

## 代码索引

开启时，工作区会用语法树一类方法建「定义 / 引用」图，并随文件变化增量更新。它让 Agent 少靠盲目全文搜索。可在功能开关里关掉（内网、超大仓库、资源敏感时）。

这不是用户手动维护的「知识图谱产品」，而是给工具用的加速器。对外不必单独卖成功能名，除非索引本身成为售卖点。

---

## 工作区与远程

多数用户的工作区就是本机目录。架构上，同一套请求也可以经中枢打到「工作区服务」，供代理模式或远程采样使用。对产品：

- 本机 TUI：工作区进程就在身边
- IDE：编辑器通过协议复用同一套文件/Git/搜索
- 未来或内部的远程工地：协议已留了门，但默认故事仍是「在你这台电脑上干活」

---

## 环境变量与机密

工作区还会处理「子进程能看见哪些环境变量」。这和文件沙箱正交：即使写不进 `.env`，命令仍可能继承已导出的密钥。企业故事里要同时说：

- 沙箱 deny 密钥文件
- 过滤子进程环境
- 不要在提示里粘贴密钥（出去的日志会尽力脱敏，但模型输入是另一回事）

项目可以按配置决定是否加载 `.envrc` 一类文件。

---

## 和「尊重 gitignore」

有一项工具级开关：是否让每个工具都跳过被忽略的文件。默认往往是不强制跳过——因为 Agent 有时必须看构建产物或本地配置才能修问题。团队若不想让模型看见忽略文件，应打开该开关，并配合权限规则。

`@` 附件选择器默认尊重 gitignore，这是**人在挑文件**时的体验，和工具自己扫盘可以不一致。讲清楚「你手动贴的」和「它自己找的」用的不是同一套过滤，能减少「为什么它能看见 `.env`」的客诉。

---

## 读完本章你应该能讲清

- 工作区 = 这份目录上的事实来源。
- 编辑会留下差异归因和按提示的回退包。
- Git 提交、回退点、对话日志是三条历史。
- 共享工地和隔离工作树是并行时的关键产品选择。
