# 13 扩展体系

Grok Build 不把「可定制」收成一个商店按钮。它提供五条平行通道，外加一条可选的长期记忆。选错通道，团队会把规范写成会执行的脚本，或把门禁写成模型也许会读的散文。

---

## 一张总表

| 通道 | 是什么 | 何时出现 | 会不会跑代码 | 信任 |
|---|---|---|---|---|
| **项目规则** | Markdown 宪法 | 每次进系统提示 | 否 | 无需（纯文本） |
| **技能** | 某道工序的作业指导书 | 相关，或用户打 `/名字` | 否（正文是提示） | 目录优先级；可用忽略/禁用 |
| **插件** | 技能+命令+智能体+钩子+MCP+LSP 的安装包 | 安装并信任后加载 | 其中钩子/MCP 会 | 项目插件要信任；用户/会话目录通常已信任 |
| **钩子** | 生命周期回调（命令或 HTTP） | 固定事件点 | 是 | 全局已信任；项目要文件夹信任 |
| **MCP** | 外部工具服务器 | 模型调用时 | 是（外部进程/HTTP） | 项目级要信任；有独立凭证 |
| **记忆** | 跨会话便笺 | 检索命中 | 否 | 总开关，默认关 |

记忆见 [11](11-记忆压缩与上下文.md)。下面只讲前五条。

---

## 项目规则：写进仓库的宪法

放 `AGENTS.md` 或规则目录里的 Markdown。Agent **每次**都看见，从家目录到当前目录一层层叠，近处覆盖远处。

适合：语言与测试约定、目录职责、安全红线的**文字版**、评审清单。

不适合：必须强制执行的拦截（模型可能没执行好）。要强制，用钩子或权限规则。

兼容其它助手的同名文件，减少「为 Grok 再写一份宪法」。

---

## 技能：可复用的 playbook

一个目录一份 `SKILL.md`：头信息说明「我是谁、何时用」，正文是步骤。描述写得越具体，模型自动选用越准。

发现从当前目录、仓库、用户家，以及可选的 Claude/Cursor 技能树。同名高优先覆盖。不走 gitignore——被忽略的 `.claude` 里的命令仍然会被加载，除非用技能配置显式忽略或禁用。这是刻意的：很多团队把厂商目录标成本地文件，但仍希望 `/frontend` 能用。

扁平底下的命令 Markdown 会变成用户可打的斜杠命令，兼容旧习惯。

适合：提交说明规范、发布步骤、评审口吻。太短的约定请写进规则；太长又要带钩子和 MCP 的，请打成插件。

---

## 插件：一键能力包

插件是目录约定（或带一份清单改路径）：

- 技能、斜杠命令、智能体定义
- 钩子
- MCP 配置、LSP 配置

团队可以把「部署技能 + 审查员 + 发布前钩子 + 工单 MCP」打成一个包。安装途径：

- 仓库 `.grok/plugins/`（给同事，要信任）
- 用户家目录（给自己，已信任）
- 配置里的额外路径
- 命令行 / 会话级目录（调用方完全控制，已信任，用完即走，不落盘到「已安装」）
- 市场源（官方或自建 git）

市场可以要求远程安装必须钉死到某一个提交。远程插件**没有密码学签名**；企业应自建源 + 钉提交，而不是指望「官方市场 = 安全」。

界面里扩展弹层有五个页签：钩子、插件、市场、技能、MCP。这是同一套生态的五个面，不是五个无关产品。

Leader 模式下，进程级「再塞一个插件目录」会被忽略——共享总台用自己的发现，避免每个窗口偷偷塞一套钩子。

---

## 钩子：门禁和自动化

在固定生命点跑命令或打 HTTP。典型点包括：会话开始、使用工具前/后、一轮结束、子代理结束、压缩前后等。

产品价值：

- **拦住**：使用前可以拒绝危险命令
- **不让收工**：结束钩子可以要求「测试没绿不准停」，并把原因喂回模型
- **记账与通知**：用后写审计、发消息
- **开工准备**：导出环境、拉依赖

默认失败放行：钩子挂了不应把主流程焊死。若合规要求「钩子没答就不能干」，要在方案里改成失败拒绝，并接受可用性代价。

项目钩子第一次要信任。信任和 MCP/LSP 共用文件夹名单：信了就一起信。全局钩子目录在若干沙箱档下还被内核禁止改写，防止 Agent 给自己开门。

钩子发现做快照，**新会话才重新读盘**。改完钩子文件却还在旧会话里等热更新，会以为「没生效」。

厂商事件名有别名，方便从其它助手迁过来。以用户指南事件表为准。

## MCP：给模型的外部工具总线

MCP 是行业协议：外部服务声明自己有哪些工具，Grok 当作模型可调用的动作。传输常见为：拉起本地进程，或连 HTTP/事件流。

配置在用户或项目 TOML。项目从根走到当前目录都可以声明。OAuth 由 Grok 编排，凭证单独存放。托管 MCP 可以在多个会话间复用登录态，过期再登。

工具多时，不会全部塞进系统提示，而是先搜索再调用，或使用 `服务器__工具名`。权限按这个名字写。输出过大就截断并落到会话目录。

适合：工单、内部 RPC、文档库、浏览器自动化一类「不是通用读文件」。不适合替代内置读改跑——那些已经在内核里，再接一层只会更慢、更难治理。

`/mcps` 开关运行时可见的服务器。文件夹不信任时，项目 MCP 保持安静，避免克隆一个仓库就被拉起未知进程。

## 怎么选（决策）

```text
只是希望它每次都记住约定
        → 项目规则

某类任务有固定步骤，有时才做
        → 技能

步骤 + 人格 + 外部系统 + 门禁要一起分发
        → 插件

必须拦住或必须留审计，不能靠自觉
        → 钩子（可再叠加权限规则）

要调用公司或 SaaS 的 API
        → MCP（可打进插件）

希望下周的新会话还记得今天的决定，且暂时不想改文档
        → 记忆（实验，默认关）
```

反模式：

- 把「禁止删库」只写在 AGENTS.md 里
- 用技能代替权限规则
- 把未钉提交的远程插件当生产依赖
- 在不信任的仓库里开项目 MCP
- 用 MCP 再包一层 `git status`

## 和智能体定义的关系

自定义智能体档（`.grok/agents/`）是第六条「人格通道」，见 [05](05-智能体与提示组装.md)。插件可以自带 agents 目录，等于把人格也打进包。子代理人格（`.grok/personas/`）又是一层行为皮肤，见 [09](09-子代理与协作.md)。

对用户不必一次抛出所有名词。对外可以只说：**规则、技能、插件、钩子、外部工具**。智能体档和人格留给已经在用子代理的团队。

---

## 读完本章你应该能讲清

- 五条通道职责不同：宪法、手册、安装包、门禁、外部手脚。
- 纯文本无需信任；会跑代码的要信任。
- 插件是打包层，不是新的能力种类。
- 选通道用「是否必须执行」和「是否要出进程」两把尺。
