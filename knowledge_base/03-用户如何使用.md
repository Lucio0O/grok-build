# 03 用户如何使用

本章按**真实用户旅程**走一遍：安装、登录、第一次说话、日常操作、把任务做大、离开后再回来。快捷键和斜杠命令的完整表在用户指南；这里讲的是**流程和选择**。

---

## 第一天

### 安装

用户在 macOS / Linux 上跑安装脚本，或在 Windows 上用 PowerShell。装好后执行 `grok --version`。之后用 `grok update` 升级。

企业可以把安装渠道换成内部镜像，再用版本策略锁住最低/最高版本——那是治理问题，见 [12](12-配置认证与企业治理.md)。

### 第一次启动

在一个代码目录里输入 `grok`。默认会打开浏览器走 grok.com 登录，凭证落到 `~/.grok/auth.json`，之后自动续期。没有浏览器的环境改用 API Key、设备码、公司 SSO 或外部登录脚本。

登录成功后，屏幕分成两块：

- **回滚区（Scrollback）**：历史。用户的话、模型的话、思考、工具、待办都在这里。
- **提示区（Prompt）**：底部输入。回车发送。

这就是日常驾驶舱。没有单独的「项目向导」：当前目录就是项目。

### 第一次任务

用户输入自然语言，例如「看看认证是怎么做的」。模型会读文件、搜索、列目录，把发现写在回滚区。默认情况下，**改文件和跑可能有副作用的命令会先问一声**。只读类操作通常不问。

用户可以用 `@` 把文件或行范围贴进提示，模糊挑选器会出来。默认避开 gitignore 和点文件；前面加 `!` 可以搜隐藏文件。

## 每天怎么交互

### 说话的几种方式

| 方式 | 用户动作 | 产品含义 |
|---|---|---|
| 普通提示 | 打字回车 | 开启一轮 |
| 附件 | `@路径` | 把文件内容带进这一轮 |
| 斜杠命令 | `/resume`、`/plan` 等 | 先走宿主内置能力，不一定叫模型 |
| 技能命令 | `/commit` 这类由 SKILL.md 提供的名字 | 把预写好的步骤包注入会话 |
| 排队 | 一轮进行中继续打字 | 下一条等当前轮结束；也可「立刻发送」打断 |
| 语音 | 快捷键或 `/voice` | 只听写成文字，不直接执行 |

斜杠命令分三类，出现在同一个菜单里：运行时内置、界面内置、技能/自定义命令。对用户不必解释分类，但产品设计时要避免同名冲突：高优先级来源会盖住低优先级同名技能。

### 焦点与取消

- `Tab` 在输入框和回滚区之间移动。
- 一轮进行中，`Esc` 取消这一轮（极简模式即使开了 Vim 也会取消）。
- 输入框有草稿时，第一次 `Ctrl+C` 只清空草稿；空了再按才取消/退出。
- 空闲且输入为空时，短时间内连按两下 `Esc` 会打开回退点列表——这是「我后悔了」的主路径之一。

这些细节看起来像快捷键问题，其实是**状态机**：取消的是「当前轮」，清空的是「未发送草稿」，回退的是「已经落盘的历史和文件」。三件事不要做成一个按钮。

### 许可怎么点

默认模式：遇到写文件或非只读命令，弹出许可。用户可以：

- 只同意这一次
- 对这个项目记住「以后类似命令都允许」（可配）
- 打开「一律放行」（`Ctrl+O` / `--yolo` / `/always-approve`）

企业可以锁死「一律放行」，用户界面上的开关会失效。无头模式不会停下来等人点，未覆盖的操作会被取消并回报给模型。

### 模式切换

`Shift+Tab` 在会话模式间循环，典型顺序是：普通 → 规划 → 一律放行 → 回到普通。`/plan` 则明确进入规划。规划模式下除会话目录里的 `plan.md` 外不能改别的文件，即使开了一律放行。这是产品上把「先想清楚」做成硬约束，而不是靠模型自觉。

## 把一件事变大时的路径

用户很少只发一句就结束。产品准备了几条「升级路径」，对应不同不确定性。

| 用户心里的状态 | 建议路径 | 章节 |
|---|---|---|
| 任务清楚，直接干 | 普通对话 + 默认权限 | 本章、[06](06-工具与能力地图.md) |
| 方案有好几种，先对齐 | 规划模式 | [10](10-计划目标与工作流.md) |
| 要并行查代码、写代码、跑测试 | 子代理 | [09](09-子代理与协作.md) |
| 编译/服务器要挂很久 | 后台命令、`Ctrl+B`、监视器 | [10](10-计划目标与工作流.md) |
| 同一句话要定时再问 | `/loop` | [10](10-计划目标与工作流.md) |
| 目标必须真正完成，不能口头说完 | `/goal` | [10](10-计划目标与工作流.md) |
| 多阶段、多 Agent、要可重放 | 工作流脚本 | [10](10-计划目标与工作流.md) |
| 明天还要记得今天的约定 | 项目规则或记忆 | [13](13-扩展体系.md)、[11](11-记忆压缩与上下文.md) |

Dashboard（`Ctrl+\` 或 `/dashboard`）用来看「我同时开着的那些顶层会话」，不列出子代理——子代理算在父会话的工作里。

## 离开再回来

会话自动保存。用户不必「另存为」。

- 欢迎页列出当前目录最近的会话
- `/resume` 打开选择器，可按标题和内容搜
- 命令行 `grok -c` 继续本目录最近一次
- `grok --resume <id 或标题>` 精确恢复
- `/fork` 从当前对话分出一条平行线，可选新的 Git 工作树
- `/rewind` 把文件和对话一起退到某次用户提示之前
- `/new` 丢掉当前上下文，开新会话（磁盘上旧的还在）

如果 TUI 崩溃，家目录里会留下「当时开着哪些会话」的痕迹，下次启动可以提示恢复。这是产品对「终端程序被杀」的补偿，不是完整的崩溃一致性数据库。

## 三种入口怎么选（给方案和售前）

| 场景 | 入口 | 关键配套 |
|---|---|---|
| 个人日常开发 | TUI | 默认权限 + workspace 沙箱（可选） |
| 结对/现场演示 | TUI + Dashboard | 多个会话并行，peek 看进度 |
| 一次性仓库问答 | `grok -p` | 只读工具白名单 |
| CI 改代码或写检查 | `grok -p` | `dontAsk` + 窄 allow + 沙箱 |
| 编辑器内嵌 | `grok agent stdio` | 由 IDE 画许可和差异 |
| 浏览器里盯远程机器 | Agent headless + 中继 | 需要 grok.com 会话 |
| 团队统一技能和钩子 | 任意入口 | 插件或仓库内 `.grok/` |

同一账号、同一 `~/.grok/`，三种入口共享会话磁盘。所以「早上在 IDE 里开的会话，下午用终端 `/resume`」是正路，不是彩蛋。

## 用户会碰到的配置表面（只需知道有这些）

用户不必第一天就改配置。真正会碰到的入口是：

- 对话里的 `/settings`、`/model`、`/theme`、`/mcps`
- 家目录 `~/.grok/config.toml`（全局习惯）
- 仓库 `.grok/config.toml`（MCP、权限、插件——可进版本库）
- `AGENTS.md`（给 Agent 的项目宪法，不是给 grok 程序的开关）

优先级和治理见 [12](12-配置认证与企业治理.md)。对用户讲优先级时用这句就够：**命令行大于环境变量大于个人配置，组织硬性要求能盖住运营活动和用户偏好。**

## 成功的一天长什么样（验收叙事）

一个产品经理可以用下面这条故事验收「主路径没断」：

1. 安装并登录
2. 在仓库里启动，用自然语言完成一次只读探索
3. 批准一次文件编辑，在回滚区看到差异
4. 用 `@` 附上一个文件再问一问
5. 打开规划模式，批准或打回一份 `plan.md`
6. 把一次长命令打到后台，继续说话
7. `/resume` 昨天的会话，上下文还在
8. 用 `/rewind` 撤销刚才那批文件改动

如果这 8 步成立，产品的主干就成立。子代理、Goal、MCP、企业锁是主干上的枝。

## 斜杠命令全景（按用户意图）

斜杠是「先走宿主、不一定叫模型」的入口。完整帮助在用户指南第 4 篇；产品经理按意图记分类即可。内置同名永远压过技能；技能可用 `/local:名字` / `/user:名字` 消歧。

| 用户想做 | 典型命令 |
|---|---|
| 换会话、回去、另开一条 | `/new` `/resume` `/home` `/fork` `/rename` |
| 后悔或腾窗口 | `/rewind` `/compact` `/context` `/session-info` |
| 带走对话 | `/copy` `/export` |
| 换脑子或换规矩 | `/model` `/effort` `/always-approve` `/auto` `/plan` `/view-plan` |
| 改编辑习惯 | `/vim-mode` `/multiline` `/minimal` `/fullscreen` `/compact-mode` |
| 记忆 | `/memory` `/flush` `/dream` `/remember` |
| 扩展 | `/hooks` `/plugins` `/marketplace` `/skills` `/mcps` `/config-agents` `/personas` |
| 挂着跑 | `/loop` `/goal` `/workflow` `/workflows` `/deep-research` |
| 媒体（视档位） | `/imagine` `/imagine-video` |
| 体检与帮助 | `/doctor` `/docs` `/tutorial` `/release-notes` `/theme` `/settings` `/feedback` |
| 账号 | `/login` `/logout` `/usage` `/privacy` |
| 从别处迁来 | `/import-claude` |

`/btw` 是旁白：给模型看、不当主任务。`/history` 翻自己说过的话。不要把斜杠菜单做成第二套设置中心——能放进 `/settings` 或扩展五页签的，就不要再占一个根命令。

## 读完本章你应该能带用户走通

- 第一天：安装、登录、当前目录即项目。
- 每天：提示、附件、斜杠、排队、许可、模式。
- 变大：规划 / 子代理 / 后台 / 目标 / 工作流。
- 回来：恢复、分叉、回退。
