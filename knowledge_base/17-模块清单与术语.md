# 17 模块清单与术语

最后一章给需要对齐工程目录、或听不懂会上名词的人。先按产品层列模块，再给中英对照。实现细节仍从略。

---

## 怎么读这张清单

每个条目只回答：**它在产品里负责哪一块**。路径相对于仓库根目录。`crates/codegen/` 是主体；`crates/common/` 是被多家共用的叶子；`prod/mc/` 是和对话代理网关共享的类型；`third_party/` 是内嵌的上游源码。

用户安装的命令 `grok` 来自 `xai-grok-pager-bin`。其余包都是它的零件。

| `ptyctl` / `ptyctl-cli` / `pager-pty-harness` | 无头伪终端，给界面自动化测试用，不是用户功能 |

## 模块如何拼成用户故事（复习）

```text
用户打开 grok
    pager-bin → pager 画欢迎/对话
    shell 成为总台或连上已有总台
    auth 确认人是谁
    config 算出这次的开关和红线
    agent 拼好「我是谁」
    workspace 盯住当前目录
    tools + sandbox + permission 接手模型点的菜
    chat-state + sampler 和模型来回
    pager-render + markdown 画出来
    会话目录记下一切
```

任意用户故事卡住，先问卡在上图哪一格，再决定是改界面、改策略还是改云端。

## 维护这份知识库

仓库是单体同步切片。大改总台、工具、权限或会话磁盘格式后，应回看对应章节是否仍成立，尤其是：

- 闸门顺序（钩子 → 规则 → 记忆批准 → 只读放行 → 模式）
- 规划是否仍不管子代理写文件
- 无头是否仍不等待许可
- 压缩默认是否仍是整段替换
- 记忆是否仍默认关闭
- 三扇集成门的传输限制

数字和旗标以用户指南与当前代码为准；本库保持原理稳定，避免变成第二份会过期的命令参考。
