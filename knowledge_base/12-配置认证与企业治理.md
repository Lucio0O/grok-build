# 12 配置、认证与企业治理

个人开发者只需要登录、偶尔改默认模型。到了团队和企业，问题变成：谁说了算、凭证放哪、组织怎样锁住不安全的开法。本章把**体验层优先级**和**真实合并层**分开讲，避免售前只背一句「命令行最大」而漏掉管理员盖章。

---

## 配置：用户能听懂的优先级

对大多数功能开关，可以这样讲（高到低）：

1. 这一次的命令行参数
2. 环境变量
3. 用户 `~/.grok/config.toml`
4. 组织下发的托管 / 硬性要求
5. 内置默认

项目里的 `.grok/config.toml` **不是**这份总表的完整副本。它主要承载 MCP、插件、权限等「跟这个仓库走」的项，并且从仓库根走到当前目录一层层叠上。

界面外观另有 `pager.toml`。沙箱另有 `sandbox.toml`。各管各的，避免一个超级文件。

---

## 配置：实现上实际叠了哪些层

真正从磁盘叠出来的底座更细：

```text
系统托管（管理员机器级）
  → 用户侧托管副本（自动维护）
  → 用户自己的 config.toml
  → 用户硬性要求
  → 系统硬性要求
  → 系统管理策略（例如 macOS 设备管理）
```

叠完之后，还可能打上**远程运营活动**（改默认模型、推功能、发公告）。活动可以来自远程或本地声明，用户能关掉某条。打完活动，**硬性要求再盖一次**，防止低信任的运营字段压过管理员。

因此企业故事是：

- **托管配置**：组织建议或默认，用户有时还能用自己的拒绝/询问压过某些允许
- **硬性要求**：组织红线，活动也压不穿
- **设备管理**：在支持的平台上比用户文件更高
- **运营活动**：可关的产品实验和公告，不是安全边界

硬性要求可以「失败就拒绝启动」。无效的版本覆盖会导致**整层硬性要求不生效**——这是保护，也是配置事故时要查的点：宁可不套坏规则，也不带着半套红线跑。

远程托管缓存有同步标记，防篡改靠签名和操作系统，不靠缓存文件自己。

## 认证：几种门，给不同的人

| 方式 | 谁用 | 要点 |
|---|---|---|
| 浏览器登录 grok.com | 个人默认 | 打开浏览器，凭证进 `auth.json`，自动续期 |
| API Key | CI、无浏览器 | 环境变量；和会话并存时，文档指出谁优先以当前指南为准 |
| 设备码 | 远程无浏览器但又要用户账号 | `grok login` 的设备流 |
| 公司 SSO（OIDC） | 企业 IdP | 本机回环回调 + PKCE；通常还要把 API 指到公司代理 |
| 外部登录脚本 | 隔离虚拟机、自建认证 | Grok 只跑命令、从标准输出收令牌，不管你怎么登 |

凭证文件只给本机用户读。MCP 的 OAuth 另放一处。登出清除缓存。

休眠唤醒时会小心处理续期，避免笔记本合盖一晚上，醒来认证状态错乱。这是稳定性，用户只觉得「不需要重新登录」。

账号还带着团队、部署、组织等身份，给遥测和权限用。编码数据是否留给 SpaceXAI 是**另一条**开关，默认偏不留，见 [16](16-观测隐私与更新.md)。

## 模型与推理出口

默认连 SpaceXAI 的编码模型。用户可以：

- 换内置目录里的其它模型
- 配自定义端点（三种常见协议方言）
- 给搜索、图像、摘要指定专用模型
- 用运营活动临时改默认

企业常做的是：把推理指到公司代理，配合 SSO，并关掉「去网上拉模型目录」（功能开关里的远程拉取），好在隔离网里跑。

推理层自带重试、取消、异常循环保护、鉴权失败刷新一次。对外不必讲算法，只要知道「偶发失败会自己试，真坏会停」。

## 版本与自动更新

启动可以检查更新，后台或提示安装。渠道（稳定 / 预发）影响看到哪条线。

组织可以下发：

- 软最低：劝你别降得太低
- 软最高：劝你别升太猛
- 硬边界：不在范围内就拒绝启动

硬边界仍然允许走更新命令自救，避免「锁死又不能升级」的死结。层与层之间只能越收越紧，不能用下层放宽上层。

## 企业治理清单（售前可用）

1. **身份**：SSO 或外部脚本，凭证不进仓库
2. **推理出口**：公司代理地址
3. **红线文件**：系统级硬性要求（锁 YOLO、钉版本、关遥测内容）
4. **托管默认**：模型、沙箱建议档、权限底稿
5. **项目宪法**：`AGENTS.md` 进 git
6. **可执行门禁**：Hooks + 文件夹信任
7. **工地围栏**：沙箱档 + 拒绝密钥路径
8. **扩展来源**：插件市场必须钉提交，或只用内源
9. **观测**：要嘛关产品分析，要嘛开企业自己的用量导出
10. **隔离网**：关远程拉目录、想清楚 MCP 和更新通道

用户指南里的企业样例和本清单对应，落地时两份一起看。

## 兼容其它助手的配置

Grok 能读 Claude / Cursor 的部分规则、技能、钩子、设置。这是为了降低迁移成本，不是承诺「100% 行为一致」。兼容扫描可以按厂商关掉。

一律放行的「组织锁」以 Grok 自己的硬性文件为准；其它产品同名锁不一定被理会。写迁移说明时单独点出这一条，避免安全团队以为旧锁自动生效。

## 家目录里还有什么（地图）

不必背全，知道分区即可：

| 区域 | 内容 |
|---|---|
| 凭证 | 登录、MCP OAuth |
| 配置 | 用户配置、托管副本、硬性要求、外观、沙箱 |
| 会话 | 所有对话和检查点 |
| 扩展 | 技能、钩子、插件、工作流、智能体定义、人格 |
| 记忆 | 若开启 |
| 信任 | 文件夹信任名单 |
| 崩溃与更新 | 上次崩溃痕迹、版本缓存 |

`GROK_HOME` 改的是整棵树。企业备份/漫游策略按这棵树设计，不要只备份某一个 json。

## 读完本章你应该能讲清

- 对用户：命令行 > 环境变量 > 个人配置 > 组织 > 默认。
- 对管理员：硬性要求盖运营活动；系统文件才是真锁。
- 五种登录门对人，不混成一种。
- 治理是身份、出口、红线、围栏、扩展来源一起做。
