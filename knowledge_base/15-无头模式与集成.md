# 15 无头模式与集成

Grok Build 的大脑可以不带驾驶舱工作。脚本、CI、编辑器、网页只要按约定说话，就能开会话、送提示、看工具、答许可。本章按集成方分类，讲清该选哪扇门、各扇门的限制。

---

## 三扇门

| 门 | 命令印象 | 进程寿命 | 输出 |
|---|---|---|---|
| 无头单次 | `grok -p "……"` | 干完就退 | 标准输出上的文本或 JSON |
| Agent 标准流 | `grok agent stdio` | 由客户端保活 | JSON-RPC 一行一条 |
| Agent 服务 / 中继 | `serve` 或 headless 连中继 | 长驻 | WebSocket |

另外，本机 TUI 自己也是客户端，经总台连同一套会话。所以「集成」不是另一套产品，是换皮肤。

---

## 无头单次：给脚本和 CI

一条提示进去，工具照常跑，结果打出来，进程结束。也可以接续或分叉旧会话，或指定工作目录、模型、力度、沙箱、规则。

### 集成时必配的安全

无头**不会在终端里等人点许可**。本该询问的调用会被取消并告诉模型。因此：

- 要它真能干：准备允许规则，或在受控环境开一律放行
- 要它别乱干：许可模式用「别问我」，再写窄允许
- 用工具白名单/黑名单限制手脚（这组旗标只在无头生效，TUI 里会警告后忽略）
- 用轮次上限防止空转烧钱
- 需要的话禁止子代理或某类子代理

### 输出怎么给下游

| 格式 | 下游怎么用 |
|---|---|
| 纯文本 | 人读、或只关心最后一段话 |
| 整包 JSON | 跑完再解析：最终回复、工具轨迹、用量 |
| 流式 JSON | 边跑边画进度条或写日志 |
| JSON 形状约束 | 最后一包必须符合你给的字段表，方便机器直接入库 |

提示可以来自参数、文件、JSON 块；「原文照送」避免宿主再解释一遍。从管道喂仓库内容是常见用法。会话 ID 可以指定（必须是新的合法编号），脚本续跑应优先用 ID 而不是标题。

### 和总台的关系

无头作为客户端连本机总台。连不上会重试有限次。TUI 可以无限重试（能取消）。对 CI，意味着镜像里要么允许拉起总台，要么走「不要总台」的专用 Agent 进程——以当前命令说明为准。

## Agent 模式：给编辑器和自研宿主

ACP 是行业向的智能体协议：初始化 → 建会话 / 加载会话 → 送提示 → 收更新 → 中间可能问许可。

典型生命期：

```text
握手（双方报能力）
  → 新建或加载会话（带上工作目录、可选插件目录）
  → 循环：送提示 → 收流式更新 → 中间可能问许可
  → 取消、压缩、回退、换模型等扩展动作按需插入
  → 关闭或断开；会话磁盘仍在，下次可以再加载
```

更新流里有：文字块、思考块、工具、计划、用量等。xAI 还扩了文件、Git、搜索、终端、回退、压缩等，让 IDE 能画原生差异而不是只显示「它说改了」。客户端在握手时报自己的能力（会不会画终端、能不能读本地文件、默认模型、是否一律放行），总台按能力决定把哪些活路由回这个窗口。

### 标准输入输出

最常见。Zed、Neovim、Emacs 一类扩展拉起 `grok agent stdio`，双方用标准流说话。客户端要处理好：半行、背压、不要把日志打到标准输出（那会破坏协议）。

### 本机服务

绑在本机端口，用口令进 WebSocket。客户端断线再连，总台上的活还在。适合「浏览器页或 GUI 连本机 grok」，不要把绑到全网地址当默认。

### 中继

Agent 主动连到中继，网页客户端也连中继。浏览器不能在用户机器上拉进程时，用这条。无头中继路径通常要求已有 grok.com 会话，因为传输只走中继、没有本机套接字可退。

会话级插件目录由调用方传入时视为已信任，且不落到「用户已安装插件」里——这是 SDK 的正确姿势：这一次实验用的包，不污染用户全局。

---

## 协议之上，产品仍是会话

无论哪扇门：

- 会话仍落在 `~/.grok/sessions/`
- 权限、沙箱、规则、技能仍然生效
- `/resume` 在 TUI 里能打开脚本昨天开的会话（ID 对上的话）

因此集成方不要自己再发明一层「对话存储」，除非有隔离要求。隔离时换 `GROK_HOME` 比换协议便宜。

---

## 给方案的选型

| 需求 | 选 |
|---|---|
| cron 每天总结仓库 | 无头 + 只读工具 + 别问我 |
| PR 机器人改一个文件 | 无头 + 窄允许 + 轮次上限 + 沙箱 |
| 编辑器里的结对 | stdio + 由 IDE 画许可 |
| 内网 GUI | serve 绑回环 + 口令 |
| 浏览器盯远程开发机 | 中继 + 该机器上的 headless Agent |
| 一次性评测 | 无头 + 固定会话 ID + JSON 输出 |

不要用无头去冒充「长会话 IDE」——没有持久进程和许可 UI，体验会裂。不要用 stdio 去跑 cron——没人读流，僵尸进程难收。

---

## 自检与包装

`grok doctor` 看终端能力，也能给集成环境当「这台机器适不适合跑 TUI」的体检。SSH 上的剪贴板、真彩色、复用器，是现场支持的前三热。无头 CI 通常不需要 doctor，需要的是权限和网络白名单。

崩溃处理会留下上次崩溃痕迹，下次启动提示。集成方若把标准错误当协议，会把崩溃文案吃进解析器——务必把日志和协议流分开。

---

## 读完本章你应该能讲清

- 三扇门：干完就退、标准流长驻、套接字/中继长驻。
- 无头必须预先授权，不会弹窗。
- IDE 用 ACP；扩展字段让差异和 Git 能原生呈现。
- 会话磁盘是共用的，换门不换记忆体。
